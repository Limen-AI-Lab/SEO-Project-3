第二部分：系统性整理建议与架构设计
================================================================================

一、当前系统的问题与痛点
────────────────────────────────────────────────────────────────────────────

1. **Prompt 硬编码问题**
   - 所有 prompt 直接写在代码中，难以维护和版本管理
   - 修改 prompt 需要修改代码并重新部署
   - 无法进行 A/B 测试或动态调整

2. **多语言支持分散**
   - 英文和中文 prompt 通过 if-else 分支处理
   - 新增语言需要大量代码修改
   - 翻译一致性难以保证

3. **变量管理不统一**
   - 每个函数使用不同的参数接口
   - 变量命名不一致（如 topic vs selectedTitle）
   - 可选变量的处理逻辑分散

4. **Prompt 组合缺乏灵活性**
   - Prompt 各部分（角色、任务、约束）紧密耦合
   - 无法动态组合不同的约束条件
   - 难以复用公共的 prompt 片段

5. **缺乏监控和优化机制**
   - 无法追踪哪个 prompt 效果最好
   - 无法收集用户对生成内容的反馈
   - 无法进行 prompt 效果的数据分析

────────────────────────────────────────────────────────────────────────────

### 5.1 子 Agent 架构

支持三种类型的子 Agent：

1. **功能型 Agent** (Functional Agents)
   - 每个 Agent 负责一个具体任务（如标题生成、大纲生成）
   - Agent 之间通过标准接口通信
   - 可以独立升级和替换

2. **专家型 Agent** (Expert Agents)
   - 垂直领域的专家（如 SEO 专家 Agent、技术写作 Agent）
   - 可以作为顾问角色为其他 Agent 提供建议
   - 例如：SEO Expert Agent 可以审查并优化其他 Agent 生成的内容

3. **协调型 Agent** (Coordinator Agents)
   - 管理复杂工作流
   - 决策路由（根据条件选择不同的 Agent）
   - 质量控制和审查

### 5.4 插件化架构

支持第三方插件扩展系统功能：

```typescript
// 插件接口
interface PromptPlugin {
  name: string;
  version: string;
  
  // 在 Prompt 构建前执行
  beforeBuild?(builder: PromptBuilder): void;
  
  // 在 Prompt 构建后执行
  afterBuild?(prompt: string): string;
  
  // 在 AI 调用前执行
  beforeAICall?(prompt: string, config: AIConfig): void;
  
  // 在 AI 响应后执行
  afterAIResponse?(response: any): any;
}

// 示例插件：自动添加品牌声音
class BrandVoicePlugin implements PromptPlugin {
  name = "brand-voice";
  version = "1.0.0";
  
  beforeBuild(builder: PromptBuilder) {
    const brandGuidelines = loadBrandGuidelines();
    builder.addConstraint(`Brand Voice: ${brandGuidelines.tone}`);
    builder.addConstraint(`Forbidden words: ${brandGuidelines.forbiddenWords}`);
  }
}

// 注册插件
promptManager.registerPlugin(new BrandVoicePlugin());
```


六、关键技术决策
────────────────────────────────────────────────────────────────────────────

### 6.1 数据库选择
- **推荐**: PostgreSQL
  - 原生支持 JSON 字段（适合存储 prompt 模板）
  - 支持全文搜索（方便搜索 prompt）
  - 成熟稳定，生态系统完善
- **备选**: MongoDB（如果需要更灵活的 schema）

### 6.2 缓存策略
- Prompt 模板缓存（Redis）
  - 减少数据库查询
  - TTL: 1小时（可配置）
- AI 响应缓存（可选）
  - 相同 prompt + 相同变量 = 相同响应
  - 节省成本，提升响应速度

### 6.3 版本控制
- Prompt 使用语义化版本号（Semantic Versioning）
  - MAJOR.MINOR.PATCH (如 1.2.3)
  - MAJOR: 破坏性变更
  - MINOR: 新功能，向后兼容
  - PATCH: Bug 修复
- 支持版本回滚
- 保留历史版本用于 A/B 测试

### 6.4 安全性
- API Key 加密存储
- Prompt 访问权限控制
- 敏感数据脱敏（日志中）
- Rate Limiting（防止滥用）
